# Docker Craft Portal v0.1.0-rc.4

Apps now open inside the portal above a persistent bottom dock. Switch between
up to four mounted apps without reloading their unsaved state. Library and admin
navigation preserve frames. Closing, restarting and logging out offer save
prompts; expired authorization clears frames. Open separately remains available.
The workspace and feedback support Dutch and English, desktop and mobile.

## Multi-user without wildcard TLS

Set `CRAFT_SHARED_APP_MULTI_USER=true`, set `CRAFT_SINGLE_APP_URL` to a distinct,
same-site HTTPS app hostname, and leave `CRAFT_APPS_DOMAIN` empty. Point both
portal and app hostnames at the existing container with ordinary certificates.
The Unraid template includes the new option. Existing wildcard mode is retained.

Shared app storage is separated by OS/browser profiles, not portal accounts.
Accounts within one browser profile share OPFS/IndexedDB and other app-origin
storage. Changing app hostnames requires exporting/importing existing browser
projects first. Keep the existing appdata volume. See [the workspace guide](../workspace.md)
for proxy headers, migration and the accepted browser-profile boundary.

## Validation

71 regular tests pass locally. Chromium browser acceptance covers retained frames,
real WASM and worker SharedArrayBuffer, shared-profile versus separate-profile
storage, authorization, exact bridge message checks, session cleanup, mobile,
localization and clean consoles. The hardened nonroot Docker image builds and
serves shared-mode bootstrap with the required isolation headers. Release CI also
requires Firefox acceptance and AMD64/ARM64 builds before publishing.

Visual review used local synthetic apps. The cloud proxy blocks the operator's
live host and official release catalog/API, so actual ArtCraft iframe/WebGPU and
service-worker compatibility remains unverified. Use Open separately where needed.
This remains a prerelease; the explicit version tag does not move `latest`.

The rc.3 candidate was blocked by mandatory browser CI and was not published.
This candidate includes portable Firefox message-spoof/offline-recovery tests and
waits for asynchronous admin rendering; no browser acceptance gate was removed.
