# Craft Portal v0.1.0-rc.1

First release candidate of the self-hosted Docker portal for official ArtCraft
WebAssembly applications. Intended for evaluation and acceptance testing.

## Included

- First-run administrator setup, Argon2id authentication, CSRF protection,
  secure host-prefixed cookies and account/app origin separation.
- Verified release downloads, ZIP validation, atomic activation, six-hour update
  scheduling, rollback and active-plus-two-version retention by default.
- Accessible dashboard, platform-filtered native installers and admin controls.
- Checksum-verified offline backup/restore with session revocation on restore.
- Hardened nonroot Docker packaging, persistent private data, HTTPS proxy and
  Unraid deployment guidance.

## Validation and release gates

Before tagging: 64 non-browser tests passed; two Chromium integration tests
passed, including synthetic WASM and same-profile OPFS isolation. Local AMD64
container health, private volume/restart and nginx syntax checks passed.

This package and GitHub Release publish only after strict Chromium/Firefox CI,
unit tests, multiarchitecture builds and hardened native container checks pass.
Passing that pipeline does not establish genuine upstream ArtCraft compatibility.
Live official-release discovery and real-app browser/WebGPU/service-worker tests
were blocked by the development environment network policy. Native ARM64 runtime
validation and deployment-specific DNS/TLS/restore checks remain outstanding.
See docs/ACCEPTANCE.md and docs/KNOWN_LIMITATIONS.md at this tag.

Existing MVP HTTPS sessions require a new login after the cookie-name migration.
Keep app and administrator hostnames separate, configure TLS for production,
and never expose the data volume directly through a web server.

## Run

Pull the image reference shown below. See docs/deployment/README.md for Compose,
separate app origins, volume ownership, updates and backup/restore. This release
candidate should be installed by its exact version tag. The initial metadata
action also created a `latest` alias for this prerelease; that alias is not a
stability guarantee. Subsequent builds disable automatic `latest` tagging.
